## Phase 0 verification log (2026-10-21)

- Reference stack: prebuilt `ghcr.io/simstudioai/*:latest` images (revision 744846f8, a few commits behind the pinned HEAD) via a Compose-2.15-compatible copy of `docker-compose.prod.yml`; building `docker/app.Dockerfile` locally hung the Docker VM after 45 min and was abandoned for the reference app.
- Seed (`tools/seed`): ran twice against the live `simstudio` DB (idempotent); minted cookie → `get-session` 200; seeded workflows/folders listed by the API; 220 blocks, 3 workflows, 3 logs, 50 table rows counted in Postgres; scrypt password hash signs in; `--expire-session` / `--renew-session` verified.
- `sim_api` contract tests (`flutter test test_contract --tags contract`, run from `packages/sim_api` with `SIM_BASE_URL=http://localhost:3001` so `/socket.io` reaches realtime through the proxy, `SIM_TEST_EMAIL/PASSWORD` = seed account, `SIM_TEST_WORKFLOW_ID` = seeded "Mixed 20 blocks"): 3/3 pass (sign-in + get-session; socket-token + Socket.IO handshake; execute stream + reconnect replay). Against `http://localhost:3000` directly the socket test times out because Next does not serve `/socket.io`.
- Extraction (`tools/extract/run.ps1` → `generated/`): 369 blocks, 6084 tool entries, 569 trigger entries, 48 subblock types, 561 icons (192 emcn + 369 brand, 0 render failures, all compiled to `.vec`), 328 pure tool-selector tables, 255 hand-port closures across 29 blocks (`generated/closures.json`), 5 workflow fixtures with upstream serializer/diff/loop outputs, 1674 contracts as JSON Schema. `check_generated.dart` green. Open decision: `generated/dart/blocks.g.dart` is 24 MB of const literals; Phase 1/2 decides between compiling it in and loading `blocks.json` at runtime.
- Upstream endpoints (`/api/public-env`, `/api/workspaces/[id]/feature-flags`, `/api/organizations/[id]/surface-context`): `bun run type-check` inside the extraction image exits 0 with them present; `biome check` clean after `--write` formatting (remaining biome findings on untouched upstream files are a CRLF/baseline artifact of the Windows checkout). Not yet exercised at runtime: the prebuilt reference image predates them; they need a locally built app image (`docker/app.Dockerfile`, now feasible with the 16 GiB VM) before the L4 cases for them can run.

- 2026-10-22: a second attempt to build the app image locally (`docker compose ... build simstudio`, with the bun deps stage cached and the VM at 16 GiB) sat in the Next build step for 14 h and again left the Docker engine unresponsive. **Conclusion: `next build` of apps/sim is not feasible on this machine's Docker VM.** Runtime verification of the new upstream endpoints (`/api/public-env`, `/api/workspaces/[id]/feature-flags`, `/api/organizations/[id]/surface-context`, the extended `/api/auth/providers`) therefore needs either a CI-built image or `next dev` (`bun run dev` inside a container with the source mounted); until then their L4 cases stay skipped with a reason and the shapes are verified by type-check only.
- 2026-10-22 Phase 1 contract run (stack reseeded after a Docker restart wiped the volume): `phase1_contract_test.dart` 10 pass + 3 skipped (public-env, feature-flags, surface-context: 404 on the prebuilt image, by design); `sim_api_contract_test.dart` 3/3 pass. Contract files must run with `--concurrency=1`: run concurrently, both files' sign-ins plus the execute call exhaust the auth/execute rate limit and the execute test gets a 429.
- 2026-10-22 (Phase 1 shell review fix): the dev route `/dev/sse-spike` is no longer registered in the app router (`lib/app/router.dart`), so the shipped app has no spike surface. The page stays in `lib/dev/sse_spike_page.dart` for reference; to re-run spike b, add a temporary `GoRoute(path: '/dev/sse-spike', ...)` locally.
- 2026-10-22 final Phase 1 gate: every package green; the app suite failed once (586/587) under random ordering while the dev server and Docker were also compiling, then passed 587/587 on three further random seeds (2405735563, 2782940413, 3198874485). The failing test was not named in the gate output; `tools/ci.ps1` now writes `build/test-report.json` per package (JSON reporter) so the next occurrence names the test and seed. Tracked as a suspected load-sensitive flake.
