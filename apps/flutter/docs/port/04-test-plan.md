# Test plan for the Flutter port

Status: v2 (2026-10-21), revised after review (`reviews/test-plan-review-v1.md`). Follows the upstream stance (`CLAUDE.md` "Testing", `.claude/rules/sim-testing.md`, `test-audit` skill): confidence over coverage, failure modes written before code, no declaration-restating tests, end-to-end preferred, every e2e run leaves a JSON report at a caller-supplied `<SUITE>_REPORT_PATH`.

## 1. Layers

| Layer | Tooling | Proves | Where |
|---|---|---|---|
| L0 Static gate | `dart format --set-exit-if-changed`, `flutter analyze` (very_good_analysis), `tools/check_generated.dart` (counts, determinism, `UPSTREAM_COMMIT`, token snapshot vs `generated/tokens.json`), `tools/check_parity_docs.dart` (every shipped route has a spec + checklist), `tools/check_licenses.dart`, `test/e2e_surface` (every finder the e2e flows use exists) | Conventions, generated-artifact integrity, e2e surface | every PR |
| L1 Pure-Dart unit | `test`; fixtures from `generated/fixtures` | Ports produce upstream outputs; failure modes handled | `packages/*/test` |
| L2 Golden | `alchemist` in `flutter test` (VM Skia, CI goldens with obscured text/Ahem, platform goldens locally); scope capped to variants that differ in tokens; `sim_design` token-resolution tests against `generated/css-measurements.json` | Structure, spacing, colours of the design system | `packages/sim_design/test` |
| L3 Widget/behaviour | `flutter_test`, `bloc_test`, `mocktail`, fake API/socket servers | Interaction logic without a backend | `apps/flutter/test` |
| L4 Contract (live backend) | Dart tests tagged `contract` against the docker stack (HTTP, SSE, Socket.IO), `CONTRACT_REPORT_PATH`; env `SIM_BASE_URL` (the proxy origin, `http://localhost:3001`, so `/socket.io` reaches realtime), `SIM_TEST_EMAIL`, `SIM_TEST_PASSWORD`, `SIM_TEST_WORKFLOW_ID` from `seed.json`; run with `--concurrency=1` (concurrent files trip the server's sign-in/execute rate limits) | The Dart client speaks the real protocol | `packages/sim_api/test_contract` (and per package) |
| L5 End-to-end | Web: `flutter drive --driver=test_driver/integration_test.dart --target=integration_test/<suite>.dart -d web-server --profile --web-port 8087 --web-launch-url http://localhost:3001/app/ --browser-dimension 1440x900@1 --chrome-binary <chrome> --driver-port 4444` with chromedriver, the proxy forwarding `/app/*` to 8087 so the real serving model is under test. Windows: `flutter test integration_test -d windows`, screenshots via root `RepaintBoundary.toImage()`. Report `<SUITE>_REPORT_PATH` | User flows in the real app | `apps/flutter/integration_test` |
| L6 Visual + structural parity | One Playwright script (pinned Chromium, Node) captures React (`:3000`) and Flutter (`:3001/app/`) with the minted cookie, `deviceScaleFactor: 1`, `reducedMotion: 'reduce'`, `colorScheme`, fixed TZ/locale; measures per §4; `PARITY_REPORT_PATH` | "Looks the same" | `tools/parity` |
| L7 Behavioural parity | Proxy request log `(method, path-template, query-key-set, body-shape)` for a scripted action sequence on both apps; socket traffic via a spy client in the same room plus the client emit log (`--dart-define=SIM_E2E=true`); compared as multisets with ordering only for dependent calls; allow-list names RSC-side calls | "Works the same" at the API boundary | `tools/parity/network` |

Rules: Patrol is not used (no Windows support; its web runner serves the app from its own origin, which breaks cookies and CORS). Profile mode on web (debug hangs on DWDS); the OttoFrontend seams are ported: `registerFakeKeyboard` (text entry), `surfaceTestFailures`, chained `FlutterError.onError`; `pumpAndSettle` is forbidden in L5 (live backend never settles): wait on conditions with timeouts, never sleeps, no retries. Count/snapshot checks belong to L0, not tests. Failure-mode-first: each pure-Dart module's test file starts with the failure-mode list; each becomes a test that is red before the code exists.

## 2. Environment

- Stack: `docker compose -f docker-compose.local.yml -f docker-compose.flutter.yml up -d --wait`; overlay sets `POSTGRES_DB=simstudio_test` (reference-script guard: DB name contains `test`), `TRUSTED_ORIGINS=http://localhost:3001`, `TZ=UTC`, Mailpit (`axllent/mailpit`, SMTP 1025, HTTP 8025) with `SMTP_HOST=mailpit SMTP_PORT=1025 EMAIL_VERIFICATION_ENABLED=true` so OTPs are read from Mailpit's HTTP API; a second profile without SMTP proves the no-verification branch. Base URL must be loopback; secrets ≥32 chars.
- Seed: `dart run tools/seed/seed.dart --out seed.json` executes SQL through `docker compose exec -T db psql -U postgres $POSTGRES_DB -v ON_ERROR_STOP=1` (pattern of `apps/sim/scripts/test-scim-e2e.ts:153-190` and `test-mobile-e2e.ts:208-262`): user, user_stats, project, workspace, permissions, session, folders, three workflows (empty; 20-block mixed with loop and parallel; 200-block benchmark), workflow_blocks/edges/subflows, knowledge base with two documents, table with 50 rows, three execution snapshots + logs, copilot chat, API key, env vars. Fixed ids from `seed.json`, never random per run. It mints `better-auth.session_token = Uri.encodeComponent('$token.' + base64(HMAC-SHA256(secret, token)))` so every e2e starts pre-authenticated; exactly one flow exercises the login UI. Session expiry is simulated with `update session set expires_at = now()`.
- Flutter under test: `flutter build web --base-href /app/ --profile` served by `node tools/dev_proxy.mjs --static build/web` for parity captures; `flutter drive` serves its own profile build at 8087 for L5.
- Determinism (`--dart-define=SIM_E2E=true`): `package:clock` injected clock, seeded id generator, motion durations zero, `EditableText.debugDeterministicCursor`, skeleton shimmer off, no `DateTime.now()` in rendered text, pinned viewport, bundled fonts only, semantics enabled.
- Performance evidence: web via `SchedulerBinding.addTimingsCallback` frame stats written to `reportData` (and CDP tracing from the Playwright capture); `watchPerformance` only on Windows.

## 3. Per-phase plans

### Phase 0
- L0 gate and CI script in place.
- L1: `SseDecoder` (frames split across chunks, CRLF, comments, named events, `[DONE]` bare and quoted, malformed JSON frame skipped and logged, abort mid-frame); `ApiClientError` mapping (internal, validation `details[].path`, v2 envelope, 499, 413, 429 with `Retry-After`, non-JSON body); query serialisation; `UploadSession` (put vs multipart, part failure retry then abort, expired `transfer.url`, missing `upload-token` → 401, complete 409, oversize); `KeyValueStore` (quota exceeded, corrupt value, concurrent writers); operation queue (ordering, single in-flight, 5 s/15 s timeouts, retry counts, superseding same-field writes, duplicate drop, offline transition and recovery, remote-apply guard, confirmation for unknown/superseded id, join generation guard, late join success for a left room ignored); reference-token tokenizer (`<a.b>`, `{{ENV}}`, escaped, nested braces, incomplete).
- L2: goldens for every emcn-equivalent widget variant that differs in tokens, light and dark; token-resolution tests against `css-measurements.json`.
- L4 (spikes as contract tests): password sign-in through the proxy sets the cookie and `get-session` returns the user; sign-in from an untrusted origin is rejected; sign-in without an `Origin` header (desktop) passes; socket-token + handshake succeeds, token reuse after 2 min fails, 30/min cap behaviour; `POST .../execute` streams `execution:started` … `[DONE]` on web (fetch adapter) and desktop; reconnect `?from=` replays; `GET /api/public-env` (unauthenticated, `Cache-Control: no-store`) returns a flat `{ "NEXT_PUBLIC_*": string }` object whose keys all carry the prefix (the `data-public-env` attribute parsed, no `window.__ENV` wrapper); `GET /api/workspaces/[id]/feature-flags` (session member) returns `{ flags: { dashboards, "workflow-tests", changelog, "mothership-model-selector", "mothership-computer-use", "mothership-plan-mode", projects }, desktopExecutor: { available, registered } }` with every leaf a boolean, 401 signed out, 403 `{ error }` for a workspace the user cannot read and 404 for an unknown one; `GET /api/organizations/[id]/surface-context` (session member) returns `{ context: { organization: { id, name, slug, logo, memberCount }, viewer: { role: owner|admin|member, isAdmin, canInviteMembers, canConnectSearchIntegrations, canUsePersonalApiKeys, canUseSearchMcp }, connectedAccountsAvailable, mothershipAvailable, canBuild, searchAccess: { sourceMirrored, memberScoped }, settingsFeatures: { billingEnabled, hasEnterprisePlan, governanceActive, hosted, selfHosted: { [section]: boolean } }, deployment: <host-context deployment shape> }, flags: <workspace flags plus "mothership-memory-spaces">, benchmarkEnabled }`, 403 `{ error }` for a non-member; the superuser flag needs no new endpoint: `get-session` already returns `user.role` (`"admin"` is the platform admin, the value `isPlatformAdmin` reads); `isCrossSiteSessionRequest` rejection reproduced from a cross-site origin.
- Spikes with pass/fail recorded in `docs/port/spikes.md`: dev proxy + `flutter run -d chrome`; 200-node canvas benchmark (≥55 fps pan on CanvasKit and Windows); `xterm` compile.

## 4. Parity method (per screen, theme, viewport 1440×900 and 1280×800)
1. **Layout boxes.** The mapper assigns parity ids (`data-parity="sidebar.item"` in the React spec ↔ `Semantics(identifier:)` in Flutter). Playwright reads React boxes via `getBoundingClientRect` + `getComputedStyle` (color, background, border, radius, font size/weight/line-height, padding, opacity) and Flutter boxes from the `flt-semantics-identifier` DOM; a `ParityProbe` reports resolved token values via `reportData`. Gate: rect delta ≤ 1 px, token values exact, text equal, child count equal.
2. **Colour sampling** at spec anchor points in non-text zones: ΔE76 ≤ 2.
3. **Structural similarity** on masked non-text regions: SSIM ≥ 0.98 (`pixelmatch`/ssim in the Node tool).
4. **Per-component goldens from measured CSS** (`generated/css-measurements.json`) asserted by `sim_design` tests.
Output: `parity/<screen>.json` + HTML diff page. Spec checklist columns: `#`, aspect (layout | token | state | interaction | network | keyboard), React source lines, expected, Flutter evidence, status (pass | gap | verified-by-review). A phase closes when no row is empty and every `gap` is in `known-gaps.md`.

## 5. CI
Gate (every PR, `tools/ci.ps1|sh`): `flutter pub get` → `dart format --set-exit-if-changed .` → `flutter analyze` → `dart run tools/check_generated.dart` → `dart run tools/check_parity_docs.dart` → `dart run tools/check_licenses.dart` → `flutter test --test-randomize-ordering-seed random --exclude-tags contract,e2e` (unit + widget + goldens with `CI=true` + e2e_surface) → upload `**/failures/**` on failure.
Nightly: compose up with overlay → seed → `flutter build web --base-href /app/ --profile` → proxy with static bundle → contract tests → chromedriver → `flutter drive` per suite → `node tools/parity/capture.mjs && node tools/parity/compare.mjs` → Windows `flutter test integration_test -d windows` → `docker compose logs simstudio realtime` → upload `reports/` always.
Report schema (one JSON per suite): `{ suite, startedAt, completedAt, status, transport, baseUrl, upstreamCommit, flutterVersion, seed:{userId, workspaceId, workflowIds[]}, requestCount, checks:[{name, status, durationMs, error?, screenshot?, artifacts?}], httpErrors:[{method, path, status}], socketEvents?:[{event, count}], frameStats?:{avgMs, p95Ms, jank}, parity?:[{screen, theme, viewport, layout:{pass, maxDelta, failures[]}, colors:{pass, maxDeltaE}, ssim:{value, pass}, networkDiff:{missing[], extra[]}}] }`.

## 6. Exit criteria per phase
1. L0 green; L1–L3 green with failure-mode headers; L4–L5 green against a freshly seeded stack with reports attached.
2. Parity: every spec row filled; layout/colour/SSIM gates met; zero network/socket diffs beyond the allow-list.
3. Reviewer sign-off recorded in each spec.
