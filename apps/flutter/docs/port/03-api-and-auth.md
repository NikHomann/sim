# Sim backend: transport map for a Flutter client

Mapped from upstream commit 27b53561def7db4eaa9ad2f12c04ea1a0eaaf91c (v0.9.30). Paths relative to the repo root.

## 1. Auth flow

Where things live: `packages/auth/src/verify.ts` (minimal Better Auth 1.6.27 instance that only verifies one-time tokens; used by realtime), `packages/auth/src/principal.ts`. Real config: `apps/sim/lib/auth/auth.ts` (1928 lines); browser SDK `apps/sim/lib/auth/client.ts`; catch-all `apps/sim/app/api/auth/[...all]/route.ts`.

Server config: `baseURL` = `NEXT_PUBLIC_APP_URL`, base path `/api/auth`. `trustedOrigins` = base URL + `NEXT_PUBLIC_SOCKET_URL` + comma-separated `TRUSTED_ORIGINS`; Better Auth checks request `Origin` and `callbackURL` against it (POSTs from other origins are rejected, comment at auth.ts:234). Session `expiresIn` 30d, `updateAge` 24h, `freshAge` 0; `cookieCache` enabled, maxAge 5 min, versioned signed cookie. `advanced` only sets `ipAddress.trustedProxies`, so defaults apply: cookies `better-auth.session_token` (signed `token.signature`, httpOnly, SameSite=Lax) and `better-auth.session_data`; `__Secure-` prefix when https. `apps/sim/scripts/test-mobile-e2e.ts` (lines 263, 451) confirms the format `encodeURIComponent(token + '.' + makeSignature(token, secret))`. `nextCookies()` plugin.

Sign-in methods: email+password (signup disabled via `DISABLE_EMAIL_SIGNUP`; `requireEmailVerification` via `isEmailVerificationEffectivelyEnabled()`; Turnstile captcha on `/sign-up/email` if `TURNSTILE_SECRET_KEY`); social github, google, microsoft (gated by `DISABLE_REGISTRATION`).
Plugins: admin, oneTimeToken (2 min), customSession, emailOTP (6 digits, 15 min, overrideDefaultEmailVerification; OTP logged to server console if no email service), genericOAuth (`/oauth2/link`), oauthProvider (login `/oauth/sign-in`, consent `/oauth/consent`), sso / stripe / organization conditionally.
Catch-all guards: POST 404 for `organization/*` (except check-slug, set-active), `sso/*` (except `sso/saml2/*`), `request-password-reset`, `forget-password`, `email-otp/send-verification-otp` unless type `email-verification`, `oauth2/*` provider mutations. GET `get-session` returns anonymous session when `DISABLE_AUTH`.

Browser SDK: `createAuthClient({ baseURL: browser origin })` with admin, emailOTP, genericOAuth, oauthProvider, customSession, conditional stripe/organization/SSO clients.

## 2. Request conventions
`apps/sim/lib/api/client/request.ts` `requestJson(contract, {params, query, body, headers, signal})`: path params fill `[id]`, `[...x]`, `[[...x]]`; query: empty skipped, scalar arrays repeat key, objects/arrays of objects as one JSON-string param; body JSON `application/json`, GET no body. Header every call: `x-sim-client-id` (random per-tab, `lib/api/client-id.ts:9`); not required. (An `x-sim-client-info` header appears only in two test files, not in the web client.) Response validated against contract Zod schema.
Errors: non-2xx → `ApiClientError{status, message, body, code}` (`lib/api/client/errors.ts`), message from `body.message ?? body.error`. Internal routes `{error, requestId?}`; 499 client cancelled; 500 "Internal server error". Validation 400 `{error, details:[{path, message}]}`; malformed JSON 400; oversized 413. v2: `{error:{code, message, details?}}`, success `{data}`, lists `{data, nextCursor}`.
Pagination: logs `cursor`+`limit` (≤200, default 100) → `{data, nextCursor, total?, revision?, snapshotAt?}`; workflows `{data}`; folders `{folders}`; workspaces `{workspaces, lastActiveWorkspaceId,…}`; knowledge/tables `{success:true, data}`; v2 opaque cursor + limit (50, max 100). Rate-limit headers `X-RateLimit-Limit/Remaining/Reset`, `Retry-After`.
Contracts: `apps/sim/lib/api/contracts/**` via `defineRouteContract({method, path, params, query, body, headers, response})` = authoritative wire spec. React Query hooks `apps/sim/hooks/queries/` map 1:1 (workspace, workspace-host, workflows, folders, logs, kb/knowledge, kb/connectors, tables, workspace-files, workspace-file-folders, projects, environment, credentials, scoped-credentials, personal-credentials, oauth/*, mcp, workflow-mcp-servers, skills, custom-tools, custom-blocks, mothership-chats, mothership-tasks, copilot-*, chats, deployments, schedules, webhooks, organization*, subscription, subscription-data, usage-logs, invitations, api-keys, byok-keys, user-profile, general-settings, session, pinned-items, inbox, sandboxes, search-*, recently-deleted).

## 4. Streaming protocols
All SSE use `SSE_HEADERS` (`lib/core/utils/sse.ts`): `text/event-stream`, `no-cache`, `keep-alive`, `X-Accel-Buffering: no`. Frames `data: <JSON>\n\n`; keepalives are comments (`: ping` / `: heartbeat`).
1. Workflow execution (editor/session flavor): `POST /api/workflows/[id]/execute` `{…, stream:true}` (session callers default to draft state); header `X-Execution-Id`; frames `data: {type, timestamp, executionId, eventId?, workflowId?, data…}` with type ∈ execution:started|completed|paused|error|cancelled, block:started|completed|error|childWorkflowStarted, stream:chunk|chunk_reset|done|thinking|tool (`lib/workflows/executor/execution-events.ts`); ends `data: [DONE]`. Reconnect `GET .../executions/[executionId]/stream?from=<eventId>`. Headers `X-Execution-Mode: async` → JSON 202; `X-Execution-Timeout-Seconds`. Parser `hooks/use-execution-stream.ts`.
2. API/deployed flavor (non-draft execute, `POST /api/chat/[identifier]`, `/api/v2/chat`, `/api/v2/workflows/[id]/execute`): frames from `lib/workflows/streaming/streaming.ts`: `{blockId, chunk}`, `{blockId, event:'thinking', data}`, `{blockId, event:'tool', phase, id, name, status?}`, `{event:'final', data}`, `{event:'error', error}`; terminal `data: "[DONE]"` (JSON-quoted). Thinking/tool frames need `X-Sim-Stream-Protocol: agent-events-v1`.
3. Mothership chat: `POST /api/mothership/chat` `{message, contexts?, chatId?, workflowId?, workspaceId|organizationId, …}` → SSE with `traceparent` header; frames `data: {v:1, type, seq, ts, stream:{streamId, chatId?, cursor?}, trace?, scope?, payload}`, type ∈ session|text|tool|span|resource|run|error|complete; text payload `{channel:'assistant'|'thinking', text}`; types in `lib/mothership/generated/mothership-stream-v1.ts`; reconnect `GET /api/mothership/chat/stream?streamId&after=<cursor>[&source=log][&batch=true]`; encoder `lib/mothership/request/session/sse.ts`.
4. Named-event SSE: `GET /api/mothership/events?workspaceId` → `event: task_status` `{chatId, type, streamId?, ownChat?, timestamp}` + `event: rotate` (`lib/events/sse-endpoint.ts`); `GET /api/table/[tableId]/events/stream?from=N` → `data:` entries + `event: pruned|rotate` (`lib/realtime/event-stream-route.ts`).
5. Others: `/api/wand`, `/api/logs/export` (chunked CSV), `/api/desktop/inbox/stream`, `/api/mcp/serve/[serverId]`, `/api/resume/...`.

## 5. Uploads
No multipart in main workspace flows (only the help modal). Signed upload sessions:
1. `POST /api/files/uploads` `{purpose, name, contentType, size, …}`; purpose ∈ workspace_file (workspaceId, folderId?), profile_picture, workspace_logo, organization_logo, mothership_attachment, execution_attachment → `{data:{session, uploadToken, transfer}}`.
2. `transfer` = `{method:'put', url, headers, expiresAt}` (PUT bytes with exactly those headers) or `{method:'multipart', partSize, partCount}` (part URLs from `POST /api/files/uploads/[id]/parts` `{partNumbers}` with header `upload-token`, PUT each part).
3. `POST /api/files/uploads/[id]/complete` or `DELETE /api/files/uploads/[id]` (header `upload-token`).
Signed URL is cloud (S3/Azure) or local `PUT /api/v2/uploads/[uploadId][/parts/[n]]`. Contracts `lib/api/contracts/upload-sessions.ts`, `contracts/v2/uploads.ts`; client `lib/uploads/client/upload-session.ts` (3 concurrent parts, retries). Knowledge, projects, table imports use the same pattern. Downloads plain GET.

## 6. Runtime config
`DeploymentShape` `{hosted, billingEnabled, chatEnabled, azureConfigured, cohereConfigured, features:{accessControl, auditLogs, customBlocks, dataDrains, dataRetention, inbox, sandboxes, scim, sessionPolicies, sso, usageMonitoring, whitelabeling}}` (`lib/core/config/deployment-shape.ts`); flags in `lib/core/config/env-flags.ts` (`hosted` when app URL is sim.ai / *.sim.ai or `NEXT_PUBLIC_FORCE_HOSTED`; `billingEnabled` = `NEXT_PUBLIC_BILLING_ENABLED`; `chatEnabled` unless `NEXT_PUBLIC_CHAT_DISABLED`; `NEXT_PUBLIC_SSO_ENABLED`, `…_ORGANIZATIONS_ENABLED` …).

## 7. Same-origin and CORS
CORS in `apps/sim/proxy.ts` (`resolveApiCorsPolicy`) for `/api/*`: `Access-Control-Allow-Origin: NEXT_PUBLIC_APP_URL` (one fixed origin, fallback `http://localhost:3001`), `Allow-Credentials: true`, listed methods/headers, exposed rate-limit/id headers. Wildcard credential-free exceptions: `/api/auth/oauth2/*`, `/api/auth/.well-known/*`, `/api/mcp/copilot`, `/api/workflows/[id]/execute`, `/api/v2/workflows/[id]/execute`; public `/api/chat/[identifier]` reflects origin with credentials. `next.config.ts` adds only `/.well-known` ACAO `*`; no basePath; rewrites only `/favicon.ico`, `/r/:code`, Markdown fallbacks.
Other checks: Better Auth rejects auth POSTs with untrusted `Origin` (extend via `TRUSTED_ORIGINS`); `isCrossSiteSessionRequest` rejects `Sec-Fetch-Site: cross-site` on session-cookie execute calls (`lib/core/security/same-origin.ts`); cookies host-only SameSite=Lax.
Page middleware (`proxy.ts`): unauthenticated `/home`, `/workspace/*`, `/o/*` → `/login` (cookie presence via `getSessionCookie`); `/login`, `/signup` → `/home` when cookie present; `/` → `/login` when self-hosted. Workspace id not resolved by middleware; `/home` resolves server-side; clients use `lastActiveWorkspaceId` from `GET /api/workspaces`. No header required on `/api`.

Finding: a Flutter web app on a different origin cannot use cookie sessions against the internal API unchanged (single credentialed CORS origin; Better Auth origin check; host-only cookies). It works under the same origin with a reverse proxy: route a path prefix such as `/m/*` to the Flutter static build (`--base-href /m/`) and everything else (incl. `/api`, `/_next`) to Next on 3000; Next defines no route at an unused prefix. A Next rewrite or `public/` placement would mean changing the repo. The proxy must also route `/socket.io` to realtime on 3002. `getSocketUrl()` (`lib/core/utils/urls.ts`) uses `NEXT_PUBLIC_SOCKET_URL`, else page origin when not loopback, else `http://localhost:3002`.
Realtime auth (`apps/realtime/src/middleware/auth.ts`, `config/socket.ts`): `POST /api/auth/socket-token` (cookie) → `{token}` (one-time, 2 min, 30/min/user); handshake `auth:{token}`, transports websocket+polling, withCredentials; server `verifyOneTimeToken`. Socket.IO CORS allows base URL, localhost:3000, localhost:3001, `ALLOWED_ORIGINS`. Realtime env: `DATABASE_URL`, `BETTER_AUTH_URL`, `BETTER_AUTH_SECRET` (must match app), `INTERNAL_API_SECRET`, `NEXT_PUBLIC_APP_URL`, `REDIS_URL`, `PORT=3002`.
