# Known gaps (accepted parity differences)

Every row is a deliberate difference between the Flutter port and the React app, with the reason. A `gap` status in any screen spec must point here. Remove a row when the gap is closed.

| # | Area | Gap | Reason | Phase to revisit |
|---|---|---|---|---|
| 1 | Files, Skills | No live co-editing (Yjs) of markdown documents; single-editor save only | No Dart Yjs implementation. **Accepted by the user on 2026-10-21 for the first release** (plan §9 q4). | After the first release |
| 2 | Code fields | Per-field code undo stack is in memory, not persisted across reload (React persists it in `stores/undo-redo/code/storage.ts`) | `re_editor` undo is not exportable | Phase 3 (custom controller if budgeted) |
| 3 | Speech to text | Desktop has no microphone input | No plugin chosen yet | Phase 6 |
| 4 | Hosted-only surfaces | Billing/Stripe, Turnstile captcha, consent banner, PostHog/GA are built from the React code but verified by review only | Not exercisable on the local self-hosted stack | Never (documented in each spec) |
| 5 | Mobile | No sub-768px layouts | Out of scope by decision | — |
| 6 | Desktop-shell settings | `desktop`, `browser`, `terminal` settings sections and desktop-only stores are absent | They target the Electron shell | — |
| 7 | Invite accept | After a successful accept the page refreshes the session only; the React page also invalidates the `subscription`, `organizations` and `workspaces` query caches. "Sign in with a different account" signs out and navigates in-app without the `clearUserData()` store reset (React falls back to a full `location.assign` when that reset fails). The support footer links `help@sim.ai`, not `useBrandConfig().supportEmail`. | The Phase 1 query cache, store-reset registry and brand config do not exist yet (`invite-accept.md` rows 26, 29, Files) | Phase 1 data layer / whitelabel |
| 8 | Signup captcha | Turnstile is a placeholder: with `NEXT_PUBLIC_TURNSTILE_SITE_KEY` set the page renders an empty `auth.signup.turnstile` slot and never sends `x-captcha-response`, so a hosted deployment with `TURNSTILE_SECRET_KEY` refuses every Flutter sign-up ("Failed to create account") | No Turnstile widget for Flutter; hosted-only (`auth-signup.md` rows 20/27) | Hosted release |
| 9 | Organization landing | `/`, `/home` and `/o` always resolve a signed-in viewer to the `/workspace` picker; there are no `/o/:organizationId/**` routes and no `OrganizationAccessDenied` route (`entry-resolution.md` §8, rows 6, 8, 9, 29, 30) | Needs `GET /api/organizations/[id]/surface-context` (server addition) and the organization surfaces, which are not ported | Phase 5 (organization settings) |
| 10 | Workspace branding | A brand name other than "Sim" sets the window title, but the brand `faviconUrl` and `customCssUrl` are not applied (`workspace-chrome.md` row 39) | `BrandConfig` carries neither field yet, and custom CSS has no Flutter equivalent | Whitelabel pass |
| 11 | Sign-out on Windows | `clearUserData` empties the browser `sessionStorage` on web and the entry picker's in-memory stand-in on Windows, but not the auth pages' in-memory `BrowserStorage.session` (`global-behaviours.md` row 21) | That store has no clear operation (auth feature) | Phase 1 auth follow-up |
| 12 | Shell prefetch | Entry starts the host context, flags, permissions, workspaces, workflows and folders together, but not the sidebar chats list or the profile query (`workspace-chrome.md` row 33) | Neither has a data-layer cubit yet; the sidebar fetches its chats itself | When the chats/profile cubits land |
| 13 | Sidebar realtime | The `workspace-workflows` invalidation room (`useWorkspaceWorkflowsRoom`, sidebar row 73, tree row 85) joins only when a `RealtimeTransport` is registered; none is until Phase 2 registers the socket transport (plan §4.3 `SocketTransport`, §6 Phase 2). Until then edits from another tab or a teammate reach the tree through the 60 s staleness refetch only (`sidebar.dart` `_bindWorkspace` TODO). | No socket transport in Phase 1 | Phase 2 |
| 14 | Sidebar data sources | The hosted status notice never polls (`fetchStatusIndicator` is not provided: no `status.sim.ai` fetcher yet, sidebar row 41); the Tables / Files rail flyouts read empty sources ("No tables yet" / "No files yet" even when data exists) until the Phase 4 table and file lists exist; the profile menu shows no Organization link (`organizationHref` is not resolved from the host context yet). Chats are live (`GET /api/mothership/chats`). | Phase 4 data layers; status fetcher not ported | Phase 4 |
| 15 | Workflow import / export | "Import workflow" (Workflows More menu) and "Export" (row menus) are shown disabled, and the palette's "Import workflow" row is shown disabled (corrected 2026-10-22), until the Phase 2 import parser and workflow serialisation exist; "Importing..." is not modelled (`sidebar-workflow-tree.md` ambiguities, review v1 finding 25). | Phase 2 serialisation | Phase 2 |
| 16 | Palette ask mode / dates | Ask-mode Enter with text opens Home without handing the query to a chat (the Phase 4 chat handoff, `onAskSim`); palette dates are formatted en-US instead of the browser locale (no locale-aware formatter wired). | Phase 4 chat layer; no intl dependency | Phase 4 |
| 17 | Search palette groups | The palette shows Sim, Pages, Workflows and Workspaces; React also shows Tables, Knowledge Bases, Logs, Chats and Integrations (and Blocks/Triggers/Tools when editing). The parity child count for `search.palette.list` is scoped to the Phase 1 groups in `tools/parity/screens*.json`. | Those groups need the Phase 2 block registry and Phase 4 query data (`search-palette.md` phase notes) | Phases 2 and 4 |
